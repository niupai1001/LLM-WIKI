# 计划修补

计划修补（plan repair）指智能体在执行失败后，只重写计划中受影响的部分，保留其余步骤不变。它是重新规划（replanning）的一种：重新规划泛指失败后修改计划，既可以是整份重生成，也可以是局部替换；计划修补特指后者，把失败定位到具体步骤或子目标，只替换这一区域。

## 工作机制

计划修补把计划表示成可定位的结构。Plan-and-Patch 使用一种结构化计划：包含目标、有序的子目标与可执行步骤，每个子目标和步骤都有标识符，对应计划文本中的一段连续 token 区间，因此可以被单独选中和替换[Plan-and-Patch](/source/7d220dd5706f59fd)。

执行失败后，流程分两步。第一步是失败检测与区域选择：执行器根据当前计划、执行历史和环境的观察与报错，选出需要修改的步骤，或选择弃权；同时给出“修补反馈”，说明为什么这段文本需要修改。论文特别指出，失败被观察到的步骤不一定就是需要修补的步骤[Plan-and-Patch](/source/7d220dd5706f59fd)。第二步是区域填充：把计划写成“前缀 + 待修补区域 + 后缀”，在保留前缀与后缀、并给定修补反馈的条件下，只生成该区域的替换文本，替换长度可以与原区域不同[Plan-and-Patch](/source/7d220dd5706f59fd)。

Plan-and-Patch 用扩散语言模型（dLLM）填充待修补区域；它可以利用被遮盖区域的前后文重建文本。论文中的自回归对照也采用中间填充格式，因此局部修补并不专属于扩散模型。[Plan-and-Patch](/source/7d220dd5706f59fd)

## 如何使用

适用场景是长程任务中计划大体正确、只有局部假设被环境推翻的情况：工具返回了意外结果、动作前置条件判断错误、或执行中条件发生变化。此时局部替换能保留已验证的步骤，避免重新生成引入无关改动。

选择条件可以归纳为三点：计划是否结构化到能定位到步骤或子目标；失败能否被归因到具体区域；保留的上下文是否足以约束替换内容。若失败原因指向全局目标理解错误，或计划本身没有可定位的边界，局部修补的前提就不成立。

示例（非论文实验）：一个家务计划在“拿起杯子”这一步失败，因为杯子实际在另一个位置。修补只需替换该步骤及其理由字段，后续“清洗”“放回”等步骤保持不变；若整份重写，后续步骤可能被无谓改动。

实践建议（基于证据的推论）：把计划写成带显式边界和标识符的结构，便于选中区域；让失败检测器只负责定位与解释、不负责改写，把改写交给修补模型。论文的评测协议是每次失败只允许一次修补尝试、随后从初始状态重新执行，这是实验设置，不是通用操作规则[Plan-and-Patch](/source/7d220dd5706f59fd)。

## 证据与边界

当前依据主要来自一项研究（Plan-and-Patch，2026 年预印本）[Plan-and-Patch](/source/7d220dd5706f59fd)。

在受测的 ALFWorld 与 TextCraft 任务中，扩散模型减少了计划生成耗时，但这不是端到端任务耗时；它不包含环境执行等环节。[Plan-and-Patch](/source/7d220dd5706f59fd)

在未做任务特定训练的 Natural Plan 上，扩散的修补成功率（53.7%）接近自回归（27.0%）的两倍，但同一设置下自回归的生成成功率更高；修补优势主要集中在旅行规划这一子域[Plan-and-Patch](/source/7d220dd5706f59fd)。这说明“修补更强”与“整体任务更优”不是同一件事。

修补效果也受区域选择限制。改用执行历史来选区后，成功率下降；在 ALFWorld 与 TextCraft 的这一设置中，自回归模型的修补成功率更高。因此不能概括为扩散模型在所有任务上修补更强。[Plan-and-Patch](/source/7d220dd5706f59fd)

## 常见误解

**修补成功率高就代表整个系统更好。** 首次计划质量、选区能力、修补成功率和总耗时是不同指标；模型的相对优势随任务和设置变化。[Plan-and-Patch](/source/7d220dd5706f59fd)

把生成时延当作端到端时延。论文报告的时延是单次生成或修补的解码时间，排除提示构建、解析与环境执行；实际任务耗时还取决于执行器与环境交互[Plan-and-Patch](/source/7d220dd5706f59fd)。
