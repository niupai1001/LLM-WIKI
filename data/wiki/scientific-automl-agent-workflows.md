# 专业科学分析与 AutoML Agent 工作流：从任务描述到工具链与实验反馈

科学分析工作流需要取得数据、选择方法、执行处理或训练，再检查结果。PhenoAssistant围绕植物表型工具和模型组织这些步骤；AutoML-Agent面向通用机器学习流水线，规划并验证数据处理、模型与训练方案。两者都使用语言模型协调专业能力，但自动执行的范围和验证方式不同。

## PhenoAssistant：专业模型与可介入的工具链

PhenoAssistant由集中式manager选择、串联工具并汇总结果。工具箱既有确定性的分割或统计模块，也有代码编写、数据可视化、图表分析、流水线复现和检索等语言模型角色。工具的结构化描述告诉manager何时调用、接受什么输入及产生什么输出，用户可在流程中介入纠正。[S:f8a9212514d96b57]

表型感知依赖视觉模型库。模型名称和记录包含物种、任务与模型信息，使manager能按需求匹配；论文案例使用经过专门微调的模型进行叶片分割等分析。通用语言模型负责协调，不因此自动获得可靠的植物图像识别能力。[S:f8a9212514d96b57]

没有合适模型时，系统要求用户按格式提供带标注数据，再安排数据划分、增强、训练和评价，并把得到的模型纳入模型库。自动训练以真实数据和明确任务为前提；模型移到不同成像或生物条件时，仍需要检查适用性。[S:f8a9212514d96b57]

## AutoML-Agent：候选方案与实际实现分开

AutoML-Agent的manager协调数据、模型和操作等专职智能体。检索增强规划先获得任务相关知识，再生成多个候选计划；数据智能体处理数据方案，模型智能体结合这些信息提出模型、参数和预期性能。这部分使用提示驱动的免训练搜索，产出候选设计，尚不等于完成实际训练。[S:5d666092726c8b5f]

manager检查候选结果后，把选定方案交给Operation Agent生成并运行代码。这样，先做方案探索，再为候选投入实现资源；模型推测的性能必须与实际运行结果区分，不能用“预期准确率”代替实验测量。[S:5d666092726c8b5f]

验证分为请求、方案执行、代码实现三个层次：先判断任务是否信息充分，再检查方案是否满足要求，最后检查真正运行的结果。失败原因进入计划修订，用于下一轮改进。不同检查回答的是不同问题，前两层通过仍不能保证最终代码成功。[S:5d666092726c8b5f]

## 共同机制与适用边界

两者都把自然语言需求连接到专业模块，并通过中间结果组织后续步骤。PhenoAssistant着重已有植物表型工具、视觉模型及用户介入；AutoML-Agent还把数据和模型方案搜索、实际实现及失败修订分成多个阶段。它们在任务域、工具和反馈协议上不同，不能据此直接判定谁更可靠。[S:f8a9212514d96b57][S:5d666092726c8b5f]

PhenoAssistant的演示涉及植物表型提取、统计、可视化和必要训练；工具链评价还使用语言模型评分，数据分析和视觉模型选择另有任务检查。这些评价形式应分别理解，语言模型给出的高分不等于科学结果正确。作者指出复杂任务、图形理解和领域适配仍需人工检查。[S:f8a9212514d96b57]

AutoML-Agent在7类下游任务、14个数据集上验证生成流程，包含明确约束和无额外约束的设置；评测时不提供人工反馈。缺少数据、骨架代码或遇到与现有任务不同的开发流程，仍可能失败；强化学习与推荐系统等需要额外专职能力。植物表型案例和通用AutoML试验都不能直接当成任意林业工作流已经验证的证据。[S:5d666092726c8b5f][S:f8a9212514d96b57]
