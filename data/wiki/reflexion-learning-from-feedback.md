# Reflexion：把失败反馈变成下一次尝试可用的经验

语言模型智能体完成一次任务后，怎样利用失败改善下一次行动？Reflexion 的研究目的，是让智能体在少量重试中从任务反馈学习，同时保持语言模型权重不变。它把失败轨迹和评估信号转化为文字反思，保存为经验，再让后续尝试根据这些经验改变决策。论文的主要发现是，这种反馈闭环能在若干决策、问答和编程任务中改善结果；改善依赖反馈质量和模型的修正能力，也存在反思无效甚至降低成绩的情况。[S:3fb5d6b0a837235b]（第1—2页，摘要与引言；第7—8页，§4.3；第12、14页，附录A、B.1）

## 为什么失败之后还需要一种学习机制

一个智能体可以在当前任务中推理、调用工具并观察结果，但这些能力并不自动使它在重新开始时避免旧错误。论文希望处理的缺口，是如何把一次尝试产生的经验变成下一次尝试真正可用的改进信息。对大型语言模型采用基于梯度的强化学习，往往需要较多样本和计算；只给模型少量示范，则没有充分利用它刚刚经历的失败。[S:3fb5d6b0a837235b]（第1—2页，§1）

困难还在于反馈的粒度。环境给出“未完成”或一个分数，只说明结果不好，通常没有直接指出哪个行动、判断或计划需要改变。一段长任务轨迹又可能包含大量无关细节。智能体既要定位可能的错误，还要把诊断转化成具体的下一步调整。作者把这看作语言能够参与信用分配的机会：用文字解释失败，让反馈包含可执行的改进方向。[S:3fb5d6b0a837235b]（第2页，§1；第4—5页，§3）

## 核心回答：把任务反馈压缩为可重新使用的修正方向

Reflexion 将过程分成三个职责。执行者生成回答或行动；评估者判断这一轮表现；反思者结合任务轨迹、评估结果及已有经验，生成针对失败的文字反馈。下一轮任务重新开始时，执行者同时接收当前轨迹和过去的反思。改进发生在模型所读的上下文中，模型参数保持不变。[S:3fb5d6b0a837235b]（第3—5页，§3）

这里有两种记忆：当前尝试的详细轨迹提供短期状态，跨尝试保留的反思保存经过提炼的经验。论文将经验数量限制在一个很小的滑动窗口，通常为1—3条。反思因而承担着选择信息的作用：从“做过什么”进一步得到“哪里可能错了、接下来应该怎样调整”。例如，在长行动轨迹中，智能体可能一直以为自己已拿到物品；有价值的经验会把这一状态错误指出来，使下一轮先核实持有状态，而不是继续执行依赖错误前提的计划。[S:3fb5d6b0a837235b]（第4—5页，§3、§4.1）

这种设计为什么可能有效？语言模型可以直接以文字指令和解释为条件生成后续行为，反思就把稀疏反馈转换成它能够利用的上下文。作者称之为类似“语义梯度”的改进方向，但它并不计算参数梯度，也没有保证诊断正确的形式化机制。反思者仍可能误判失败原因；一条流畅的经验，只有真正改善了后续尝试，才体现出任务价值。[S:3fb5d6b0a837235b]（第1—2页，§1；第4页，§3；第9页，§5）

## 实际结果：重试变得有效，也暴露了反馈闭环的脆弱处

### 多步任务中，经验可以帮助纠正持续重复的错误

在134个 ALFWorld 文本环境中，作者采用 GPT-3，以两条领域示例轨迹提示 ReAct 生成行动，比较重试时是否加入反思。基线在触发失败或低效规划判定后也会重置环境，因此比较包含了“可以再试”和“带着反思再试”的差别。采用启发式判定的 ReAct＋Reflexion 在连续12次尝试中累计完成130个任务；ReAct 基线的改善在第6—7次尝试附近停止。[S:3fb5d6b0a837235b]（第5—6页，§4.1、图3）

这说明，在该设置中，增加重试机会不足以解释全部收益。作者观察到，反思有助于纠正“以为持有物品，实际没有”的状态错误，也能保存已经搜索过的位置，减少下一轮重复无效搜索。这里的成绩是多次尝试后累计解决的任务比例，不能理解为首次尝试就完成了130个任务，更不能直接视为已经学会处理未见过的新任务。[S:3fb5d6b0a837235b]（第5—6页，§4.1、图3）

### 问答中，反思的作用超过仅保留上一轮轨迹

HotpotQA 实验区分了给定正确上下文的推理，以及需要自己检索的问答。以附录报告的100道题为例，text-davinci-003 的 CoT（给定正确上下文）从0.60提高到0.77，ReAct 从0.30提高到0.55；同一表中的 GPT-4 两种设置分别从0.68到0.80、从0.39到0.51。给定正确上下文的设置排除了部分检索困难，其提升主要说明读懂已有材料和推断答案仍有可修正空间；它与完整检索问答的成绩不能直接混用。[S:3fb5d6b0a837235b]（第6—7页，§4.2；第12页，表5）

更关键的对照是：先把最近一次轨迹加入上下文，再增加反思步骤。论文报告，加入反思后又获得8个百分点的绝对改善。这个结果支持“保存经历”和“解释经历”具有不同作用：模型看到自己做过什么，仍可能需要明确的错误解释来组织下一轮修正。[S:3fb5d6b0a837235b]（第7页，§4.2，Analysis；图4c）

这些问答实验允许失败后继续尝试，直至某题连续失败三次，并由环境使用标准答案做精确匹配，返回对错反馈。智能体没有直接读取标准答案文本，但反馈本身依赖标准答案。因此，结果说明的是具备这种判定信号时的迭代改进，不能直接当作没有答案判定器的日常问答效果。[S:3fb5d6b0a837235b]（第6—7页，§4.2）

### 编程中，测试与反思需要协作，错误测试也会反过来伤害结果

编程实验先由模型生成单元测试，执行测试后产生反馈，再据此反思和修改实现。表1报告，HumanEval Python 的成绩从 GPT-4 基线的80.1%提高到91.0%，HumanEval Rust 从60.0%提高到68.0%；MBPP Python 则从80.1%下降到77.1%。论文使用 pass@1 表示向正式评测提交一个最终候选的准确率，候选在提交前可以经过内部测试和多轮修正；它并不等于只调用模型生成一次代码。[S:3fb5d6b0a837235b]（第7—8页，§4.3、表1—2）

50道较难的 HumanEval Rust 题提供了一个更有解释力的消融：基线为60%，同时使用测试和反思为68%；有测试、没有文字反思仍为60%；保留反思但去掉测试生成与执行则降到52%。作者观察到，没有测试指导时，智能体可能无法识别已有实现已经正确而继续做有害修改；只有测试报错而没有反思时，它又未必能把报错转成有效的实现调整。这个小规模对照支持两者的配合作用，尚不足以证明所有编程任务都必须采用相同分工。[S:3fb5d6b0a837235b]（第8页，表3及 Ablation study）

MBPP Python 的退步揭示了另一端的风险：如果自生成测试放过错误实现，智能体就会过早停止。论文报告，在内部测试已通过的条件下，正式提交仍错误的比例，MBPP Python 为16.3%，HumanEval Python 为1.4%。这将反馈质量与最终成绩联系起来：测试能够执行，不代表测试覆盖了真正要求；反思闭环也可能被错误的“成功”信号提前截断。[S:3fb5d6b0a837235b]（第8页，§4.3，Analysis）

### 反思不会自动带来探索能力或普遍收益

附录中的 WebShop 试验在100个环境中运行，作者在四次尝试后停止，因为没有观察到改善，也没有得到有帮助的反思。他们将困难解释为需要更多样、更有创造性的搜索行为。另一个边界来自模型：starchat-beta 在 HumanEval Python 上，基线和 Reflexion 的平均成绩均为0.26。前者说明既有反思可能无法使搜索跳出局部选择，后者表明同一流程的收益不能脱离执行模型的能力讨论。这些失败结果界定了适用范围，并未单独证明探索困难或模型规模就是唯一原因。[S:3fb5d6b0a837235b]（第12页，附录A、表4；第14页，附录B.1、图6）

## 从这些结果可以得到什么认识

### 语言经验可以成为固定权重智能体的任务内适应手段

智能体的行为取决于模型参数，也取决于它当前读到的经验。Reflexion 展示了一条保持参数不变的适应路径：把失败转换成能够影响下一次决策的文字，再通过上下文重新使用。ALFWorld 的累计改善，以及问答中反馈引导的重试，支持这种方式能在部分任务上产生实质收益。它适合说明“同一任务多次尝试之间如何积累经验”，还不能据此声称智能体已获得跨任务、长期稳定的能力增长。[S:3fb5d6b0a837235b]（第3—7页，§3、§4.1—4.2）

### 有用的记忆要提供修正方向，保存轨迹并不足够

一段历史记录只保留事件，经过反思的经验还试图建立“错误—原因—下一步改变”的关系。HotpotQA 的记忆消融表明，最近轨迹之外加入反思仍有增益；Rust 消融则表明，测试指出失败后，缺少解释和修正衔接也可能无法改善实现。由此得到的知识是：为任务设计经验记忆时，需要关心它是否让下一次决策发生有依据的改变，不能只以历史保存量判断记忆是否有效。该认识由这两组实验支持，具体采用何种总结形式仍需要随任务验证。[S:3fb5d6b0a837235b]（第7页，§4.2，Analysis；第8页，表3及 Ablation study）

### 评估信号决定修正闭环的方向，也决定何时错误地停止

反思依赖评估识别“哪里值得改”。错误的失败信号可能触发不必要的修改，错误的成功信号则可能让错误答案提前提交。MBPP Python 的负面结果与内部测试的误放行现象，说明改进生成器和设计可靠判定信号是相互关联的问题。对于能够执行测试的任务，应核对测试是否覆盖实际要求；对于需要标准答案的问答反馈，应认识到这种判定条件未必在实际使用中存在。增加反思轮数不能代替可信的评估依据。[S:3fb5d6b0a837235b]（第6—8页，§4.2—4.3，表1—3）

### 反思能利用已有经验，但不保证找到新的解法

反思要求模型既能从失败中提出有效变化，也能在下一轮执行它。WebShop 中没有帮助的反思和 starchat-beta 上没有收益的结果，共同提醒我们：配置一个反思步骤并不等于建立了有效学习。若任务需要新的搜索策略，或模型不能形成可用的修正方向，重复反思可能停留在原有局部选择中。这支持为反思流程保留能力和任务边界；它尚未给出一种经过验证、能够稳定逃离这些失败情形的替代机制。[S:3fb5d6b0a837235b]（第9页，§5；第12页，附录A；第14页，附录B.1）
