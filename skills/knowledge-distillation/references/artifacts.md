# 知识提炼产物

生成三个互相对应的文件：reading.md、knowledge.json、review.md。正文服务于理解，结构化知识服务于复核与复用，审核记录服务于纠错。

## reading.md：可独立阅读的论文解读

采用自然段和少量必要标题，围绕以下逻辑展开：

1. 论文试图解决的具体问题，以及既有方法的瓶颈；
2. 核心回答与关键设计，重点解释为什么这样做；
3. 方法如何发挥作用，哪些设计选择是关键；
4. 代表性实验证据及其解释、不能推出的结论；
5. 可复用认识、领域条件、失败情况与开放问题。

标题可随论文类型调整；理论论文、系统论文和评测论文不必套入相同结构。不要把内部审核标记、字段名、技术参数表或孤立要点直接堆入正文。

## knowledge.json：可追溯的知识

使用以下内容分区：

| 字段 | 内容 |
| --- | --- |
| source | 原文身份、版本与可读范围 |
| purpose | 具体研究目标 |
| motivation | 既有方案的瓶颈及后果 |
| central_answer | 核心回答与关键设计逻辑 |
| results | 少量代表性结果、比较条件及其解释 |
| knowledge_points | 经过提炼、具有证据与范围的知识命题 |
| source_notes | 原文缺口、重要未解释问题与必要补充 |

每个 knowledge_points 条目应能回答：

- **statement**：到底知道了什么？用完整句子表述。
- **explanation**：它为什么重要，机制或推理链是什么？
- **evidence**：原文中什么内容支持它，位置在哪里？
- **scope**：在什么任务、数据、设置或假设下成立？
- **type**：属于问题、机制、设计、证据还是边界知识；如涉及领域迁移，说明其通用、领域或桥接属性。
- **uncertainty**：哪些环节属于作者解释、提炼者推论或未知？

字段可使用字符串、对象或数组表达必要信息，但同一批次保持一致。没有依据时留空并说明原因，不填入猜测。知识点数量由实际贡献决定，不设机械配额。

不要生成页面规划、概念更新建议、主题路由或发布决策。

## review.md：独立核查记录

记录：

- 核查的原文版本与阅读覆盖；
- 核心论证是否完整；
- 重要知识点的证据支持与范围问题；
- 正文中的因果跳跃、领域泛化、重复和可读性问题；
- 每项问题的位置、严重程度、修订建议及处理状态；
- 未解决问题与最终结论。

核查结论分为 blocked、needs-revision、ready。ready 仅表示当前知识提炼成果通过本次核查，不意味着其观点在外部世界已获最终证实。

## 一致性

reading.md 的重要事实应能对应 knowledge.json 中的命题或结果；knowledge.json 的实证命题必须有真实原文依据；review.md 发现的事实问题应回到知识与正文同步修订。只改措辞不能自动消除证据问题。
