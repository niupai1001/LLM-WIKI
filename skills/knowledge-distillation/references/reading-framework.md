# 阅读与论证重建

## 阅读完整性

先通读摘要、引言、相关工作、方法、实验、消融、失败案例、局限与结论，并检查与核心主张有关的图表和附录。摘要用于定位问题，不能代替方法和证据。解析缺页、表格无法读取、公式或图示信息不足时，标记未读范围；结论只覆盖实际阅读的材料。

对不同贡献类型调整阅读重点：

| 贡献类型   | 重点追问                    |
| ------ | ----------------------- |
| 方法与机制  | 关键设计改变了什么，如何起作用，为什么如此设计 |
| 理论与范式  | 概念边界、核心假设、推理过程及反例       |
| 领域应用   | 领域特有约束、方法适配及结果可迁移程度     |
| 系统设计   | 组件之间的信息流、设计权衡及运行条件      |
| 数据集与评测 | 测量目标、样本构成、指标有效性及偏差      |
| 综述     | 分类依据、证据覆盖、共识与分歧         |

## 论证链

在内部逐项回答：

1. **目标**：作者试图解释、解决或测量什么？
2. **现状**：既有方案如何工作？
3. **瓶颈**：哪一步存在具体缺陷，后果是什么？
4. **回答**：论文的核心主张是什么？
5. **设计**：哪些选择对主张成立不可或缺？
6. **理由**：这些选择为什么可能缓解瓶颈？
7. **证据**：哪项实验、推导或案例支持哪项主张？
8. **边界**：什么条件下不能这样推断？
9. **认识**：读者可以带走什么可复用的理解？

遇到断链时区分：作者没有解释、材料没有提供、解释存在但未经检验、已有证据相互冲突。不要通过补写合理故事消除空白。

## 机制解释

优先解释输入、关键变换、状态或信息如何传递、输出如何被使用，以及该过程如何对应原始问题。技术术语首次出现时说明其作用，不用术语替代解释。

如果设计涉及多个阶段，应讲清前一步的产物为何是后一步的必要输入。若只是工程实现选择，且与核心主张无关，则压缩描述。

“作者采用某组件”和“该组件导致某结果”是不同命题；后者需要额外证据。

## 实验分析

把实验组织成“被检验的主张 → 设计与比较对象 → 观察结果 → 解释强度 → 不能推出什么”。

- 主结果用于判断目标是否在所测设置中达成。
- 消融用于判断组件或设计选择是否贡献了可观察变化。
- 误差分析用于识别失败条件与薄弱环节。
- 跨任务或跨数据集结果用于讨论迁移范围，但不能自动证明普适性。

保留决定判断的少量数字、指标、比较对象和条件；不要搬运整张排行榜。作者提出的因果解释若未被实验隔离验证，应按解释或假设表述。

## 成文要求

按问题的逻辑而非论文小节顺序写。段落承担不同任务：交代瓶颈、解释核心思路、展开机制、分析证据、限定结论。段与段之间有因果或递进关系。

写完后遮住论文标题与组件名称，检查读者是否仍能复述研究动机、解决过程与证据边界。若不能，重写结构，而不是补更多术语。
