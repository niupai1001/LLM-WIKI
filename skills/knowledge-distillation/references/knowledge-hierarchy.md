# 知识提炼层级与抽象边界

## 什么值得成为知识点

知识点不是论文的一句摘录，也不是某个组件名称。它应表达一个有解释价值、可以独立理解并能回到证据的命题。

优先识别五类知识：

1. **问题知识**：某类任务为何困难，关键约束是什么。
2. **机制知识**：某种处理、决策或反馈方式如何发挥作用。
3. **设计知识**：为什么选择某种方案，它牺牲或获得了什么。
4. **证据知识**：实验、推导或案例揭示了什么，证据强度如何。
5. **边界知识**：失败条件、反例、适用范围和未解决问题。

一个知识点通常由“命题—解释—依据—条件”组成。不要为了追求数量，把同一机制拆成零散步骤；也不要把多个独立因果判断合并成一句无法核查的大话。

## 从事实到可迁移认识

可按以下层级判断抽象程度：

- **具体观察**：特定实验或案例报告了什么。
- **条件性解释**：在给定任务与假设下，为什么可能出现该观察。
- **机制认识**：可明确描述的输入、作用过程和输出关系。
- **可迁移原则**：在多个条件或独立证据下仍有支持的规律。

层级越高，需要越强的证据。单项实验通常只能直接支持具体观察；抽象到通用原则必须保留前提，并说明证据是否足够。

## 通用性与领域依赖

对每条知识问：

- 机制的作用对象是什么？脱离原任务后仍有明确含义吗？
- 结论是否依赖某种数据语义、物理约束、专业工具或评测协议？
- 论文是否实际检验了跨领域迁移，还是仅提供可迁移的设计启发？

据此区分：

- **通用机制**：可以不依赖特定领域名称来清楚定义，但其效果仍有适用条件。
- **领域知识**：成立依赖特定数据、任务目标或专业约束。
- **桥接认识**：一般性机制与领域条件相互作用，二者都需要保留。

同一篇论文可以同时产生多种知识。不能因为材料涉及 Agent、规划、反馈或工具使用，就将其所有贡献都抽象为通用 Agent 规律。

## 避免过度提炼

- 关键词相同不代表机制相同；需比较问题、作用对象、信息流、反馈位置与适用条件。
- 表面流程相似不代表因果解释相同；保留各自的证据范围。
- 作者没有解释的设计理由不能由提炼者自动补全。
- 多篇论文报告相似结论，不一定是独立复现；检查数据、基线、设置和来源关系。
- 迁移可能性应写为启发或待验证假设，不冒充已证实规律。

## 去重与组织

多个段落支持同一命题时，合并解释并保留证据。不同条件下结论相反时，保留条件与分歧，而不是强行统一。对于仅是背景定义、常识复述或复现参数的信息，只有在理解主张确有必要时才纳入知识点。
