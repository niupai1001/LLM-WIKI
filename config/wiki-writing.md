# Wiki 编写规范 v2

这份规范供项目中的 LLM 编写器直接加载。面向理解 LLM 基础、希望把知识用于设计智能体的中文读者。

## 页面职责

- 概念页只回答一个稳定问题，标题用简短中文概念，不用论文标题串联。主题入口只负责导航，不重复概念页全文。
- 先区分读者任务：解释概念、查阅定义、操作指南、学习教程。默认生成解释型概念页；实践建议放在独立小节，不能把研究结果写成已经验证的操作规程。
- 更新已有页面时保留仍有依据的知识与引用，改写措辞和组织；不要仅在末尾追加新论文摘要。
- 同一分类不代表同一概念。候选材料跨越不同问题时，只选一个有充分证据的概念，`used_source_ids` 只列实际用于本页的本次来源；未使用资料应留待下一篇，不要为了覆盖所有材料拼成综述。优先更新已有概念页，主题入口通常保持导航职责。
- 上下文中的 `category_focus` 是用户设置的主题关注范围，用于选择知识问题与编写方向；它不是事实证据，不能替代原文或扩大结论的适用范围。留空时按候选原文确定具体问题。

## 正文结构

正文不写重复的一级标题，不生成来源列表（程序负责），不按论文逐篇罗列。概念页正文以 900–1800 个中文字符为目标，必要时最多 2600 字符。短而完整，不能为了凑模板补无依据内容。

开头用 2–3 句说明：这个概念是什么、解决什么问题、与相邻概念有什么区别。随后使用下列二级标题：

1. `## 工作机制`：用因果顺序解释输入、处理、输出。术语首次出现用常用中文加英文原词；不可用翻译腔代替解释。
2. `## 如何使用`：给出适用场景、选择条件或简短步骤，以及一个具体例子。若例子是为解释而构造的，写“示例（非论文实验）”；工程建议写“实践建议（基于证据的推论）”。不要编造实现接口、生产验证或万能结论。
3. `## 证据与边界`：保留最能支撑核心认识的 1–3 条证据，说明来源、设置和限制。必要数字必须同时写清指标、对照和实验范围；不堆叠统计量，不直接比较不同论文的指标。单篇证据明确写“当前依据主要来自一项研究”。
4. `## 常见误解`：解释 1–2 个会导致错误决策的混淆；不要重复前文或机械添加“开放问题”。

真实相关页面用 `[[slug|简短概念名称]]`；只连接已经存在且语义相关的页面。引用 `[S:来源ID]` 放在它所支持的句子或短段后，同一段同一来源不反复标注。一个引用不能替整段的无依据主张背书。

## 用词与证据要求

- “准入”应解释为“决定哪些信息进入上下文”；“呈现”解释为“同一信息如何组织成提示”；“失败归因”解释为“定位导致失败的关键步骤”。不把 attention 翻译成拟人化的专注力，不把合规率等同正确率。
- 区分论文的模型假设、观察结果、作者解释与本页推论。预印本的局部实验不代表领域共识。
- 检查时延是计划生成还是端到端；费用是任务构建还是运行评测；理论结论依赖什么假设；安全改善是否牺牲正常任务能力。
- 机制优先于排行榜。对读者决策没有帮助的 p 值、所有模型分数、附录推导和细碎开放问题移出主干。
- 用明确主语和短段落。避免“共同指向”“管线级效果”“外部面”“认识论状态”等未经解释的抽象词。避免照搬英文句法。

## 输出前自查

能否在第一段回答“是什么”？读者能否知道何时使用、何时不适用？每个核心事实能否回到原文？是否把假设或建议写成事实？是否有不必要的数字、重复标题或不存在的知识链接？

在 JSON 中另给 `editorial_notes`（简短说明页面的问题、关键术语与删去的枝节），不在正文展示自查过程。自查只是编写辅助，不代表事实已经认证。

## 证据与差异记录

编写顺序是读取原文与现有知识、确定要回答的问题、提取相关原文及其位置、比较证据范围、生成正文和结构化记录、第二遍编辑、等待发布审核。不得凭模型训练知识补充来源没有给出的公式或事实。

JSON 的 `claims` 记录 1–3 条核心断言，每条有稳定 id、简短 text、实际支持它的 source_ids、具体 scope 和支持状态。scope 写清任务、数据、模型或理论假设，并尽量指出原文章节、表格或定义位置。只有摘要不能充当全文核查。不要用“普遍适用”“来源可靠”等空话代替范围。

`多源一致` 只表示多份作品在相同问题上给出相符的表述，不代表独立验证。同一论文的版本、转载和二手引用不能变成多个独立证据；独立性需要核对作者、数据、方法及引用关系。无关的基础论文不能替具体方法背书。

`conflicts` 可以为空，不能为填字段制造矛盾。确有差异时先检查定义、版本、指标、样本和实验设置；条件不同记为范围差异，在正文分别保留。相同范围下结论相反才提出结论冲突，双方保留 source_ids 和 scope，status 为待核查，handling 写清复核步骤。模型不能自行宣布冲突已解决，不用多数来源或新论文自动替代旧知识。已有未解决记录必须保留；更新正文后原核查记录需要重新确认。
