# 来源入选与证据规范

每日 08:00 的 RSS 负责发现 Agent 候选材料。关键词、日期、来源平台和抓取成功只决定是否入库，不代表已通过质量评审。候选资料可以生成待审提案，不能直接成为共识或自动发布。

## 入选记录

每份来源记录标题、作者、原始链接、归档原件、获取时间、首次提交与修订日期、版本、出版平台、发表状态、出版 DOI 和预印本 DOI（如能核验）。RSS 推送日期单独保留，不能冒充发表日期。缺失字段明确标记，模型不得补造。元数据记录核对方法、网址、时间和逐字段依据。

入选理由应说明材料回答的具体问题、是否有完整方法与实验、是否可查代码或数据，以及哪些部分尚未复核。来源池兼顾基础方法、正式发表研究、官方工程文档和最新预印本。官方文档能支持产品使用方法，但厂商声明不等于独立效果验证。

## 判断知识而非给整篇打分

先确定具体断言，再检查对应的原文位置、实验条件、对照、方法局限和可复现信息。多份资料只有支持同一问题、范围可比时才增加证据覆盖。转载、不同版本、共享基准或同一团队工作不能自动视为独立验证。数量和模型自评百分比不能替代这些检查。

本项目把来源真实性、书目核查、全文获取、发表状态、内容核查、独立复现分开记录。Wiki 发布批准表示同意页面变更；不表示论文已同行评审或断言已证实。

## 差异与冲突

1. 保留双方表述、来源、日期与具体范围。
2. 先检查版本、定义、数据、模型、指标与实验设置是否可比。
3. 条件不同分别记录范围差异；可比条件下结论相反才记结论冲突。
4. 未解决的冲突保留在正文和结构化记录中，不按多数、新旧或模型意见选胜者。
5. 新证据或勘误可触发复核；解决说明必须给出依据，旧处理记录不能默默删除。

自动编写先提取来源证据，再综合成概念；第二遍编辑和结构 lint 只能帮助发现问题。需要人工核对的内容继续显示待核查。正文更新会失效旧的内容核查标记并保留历史，原冲突重新待核。
