# Review：独立核查与发布门禁

## 职责

定义独立于写作过程的事实、逻辑、领域范围和阅读质量核查。不能将模型自评分、摘录匹配或测试通过等同于真实事实正确。

## 核查流程

1. 冻结待核查的来源版本、结构化断言、正文和旧知识快照。
2. 核查者重新打开原文相应段落及必要上下文，不仅看作者提供的引用片段。
3. 逐断言判断 supported / partial / contradicted / unverifiable，写明理由。
4. 检查正文的事实性句子是否被断言覆盖，检查实验数字、指标、条件和限制。
5. 检查是否存在作者解释与提炼者推论混淆、因果偷换、领域泛化、旧知识遗漏。
6. 独立阅读正文，检查问题—回答—设计理由—证据—启示是否连贯。
7. 给出阻断、警告和编辑建议，修订后重新核对受影响事实。

## 三类问题

**Hard block**：无全文却声称完整提炼；关键图表未读却下结论；核心 claim 无证据或证据不支持；推论伪装作者结论；领域结果被泛化；旧断言/冲突静默丢失；版本不匹配；概念误合并；正文只是模块清单或逻辑断裂到无法解释研究主张。

**Review warning**：次要设计理由缺失、重要局限位置不清、证据覆盖较弱、重复实验结果偏多、概念路由需要更多材料。

**Editorial suggestion**：句式、术语解释、段落承接、例子和篇幅的改善；不得用表达修订偷偷改变已核查事实。

## review.md 推荐结构

- 来源身份、版本、审核者类型和核查范围；
- 核心论证链是否完整；
- 逐条问题：位置、问题类型、原文依据、影响、处理建议；
- 断言支持状态及未读材料；
- 通用/领域路由核查；
- 旧知识和冲突保留核查；
- 结论：blocked / needs-revision / ready-for-integration。

这是 Skill 审核文档，不是项目当前的正式发布批准对象。程序仍须使用原有接口与门禁。

## 五个回归样本

| 样本 | 必查问题 |
| --- | --- |
| ReAct | 推理—行动交错的动机、观察回流位置、任务范围 |
| Change-Agent | 遥感特殊性与可迁移机制并存、参数压缩、实验解释 |
| Reflexion | 语言反思在尝试间的作用、与环境观察反馈的区别 |
| 第二篇领域 Agent | 领域条件不被通用化，概念不按关键词误合并 |
| Benchmark/范式论文 | 不套方法流水线，说明评测/论证本身的有效边界 |

每个样本均检查来源完整性、论证链、机器证据、正文重复同源引用、旧概念路由与审核结果。测试用论文事实必须重新核对原文，不能用示意内容作为金标准。

## 建议的度量与起点

确定性 CI 检查：结构字段存在、ID 可引用、来源版本一致、旧 ID 保留、非法 topic 路由、重复同源引用密度异常、正文数字密度异常。后两项只能警告，不能作为事实正确的证明。

人工抽样：逐断言证据支持率、scope 保留率、错误推论率、概念误合并率、论证链可复述率、盲评阅读偏好。建议先以 3–5 篇代表论文建立基线，再制定阈值。当前仓库 candidate-v2 切换门槛已有人工逐断言支持精度至少 95%、真实混合候选 Recall@8 至少 90% 等条件，**不能用本 Skill 的自评替代**。
