# Knowledge Hierarchy：知识层级与领域 Agent 路由

## 职责

负责从单来源知识点到跨来源概念与主题的归属决策，防止领域知识被过度抽象或不同论文被关键词误合并。

## 四个层级

1. **来源（source）**：论文及其版本、原文与书目。回答“谁在什么条件下说了什么”。
2. **知识点（knowledge point）**：有依据、有范围的完整命题。回答“这份材料让我们多知道了什么”。
3. **概念（concept）**：围绕稳定问题组织、允许多来源补充和修正的知识对象。回答“这一机制如何工作、何时适用”。
4. **主题（topic）**：围绕学习问题的阅读入口。回答“应该按什么顺序理解相关概念”。

**采集 category 不等于知识 topic**；论文标题不等于概念；同一论文可贡献多个知识点、更新多个已有概念。比较页保留方法差异，来源清单负责归档，不替代机制概念。

## Domain-Agent 双重身份判定

对每个候选命题执行以下判定：

1. 明确它解决的问题、作用对象、输入、输出、反馈位置、适用条件。
2. 去掉领域名称后，该机制是否仍然有确定含义？如果是，提出通用 Agent 机制候选。
3. 原文结果是否依赖领域特有数据、空间语义、测量或工具？如果是，保留领域专用知识。
4. 若一般机制通过特定领域实例实现，则建立**桥接关系**，而不是强制二选一。
5. 检查迁移证据：没有跨领域实验时，只能说“机制具有潜在迁移价值”，不能说“已证明普适”。

### Change-Agent 路由示意

**领域专用候选**：遥感变化检测中，不同时相影像的观测对齐、变化区域的空间语义以及专业检测输出如何解释。该知识不能因为系统包含 Agent 就删去。

**通用候选**：外部感知结果如何被组织成 Agent 可利用的中间状态，以及工具反馈如何影响下一步选择。只有当原文实际提供相应机制时才提取。

**桥接候选**：某个领域感知模块为 Agent 决策提供结构化证据；通用部分是“感知到决策的信息接口”，领域约束是遥感变化信息的定义与误差性质。

上述候选需要回到原论文核实，不是预设 Change-Agent 已实现每一种机制。遥感实验中的有效性不能自动证明通用 Agent 机制在其他任务有效。

## 概念对齐规则

优先比较五个维度：所回答的问题、核心机制、作用对象、反馈位置、适用范围。名称相同但机制不同可分开；名称不同但机制与范围等价可考虑合并。单靠标题相似、关键词、embedding 分数或共同引用不足以批准合并。

决策：

- **update**：已有概念回答相同稳定问题，新材料补充证据、条件、差异或实例；
- **create**：确有新的稳定机制，已有概念无法承载，原文解释足够；
- **defer**：只有提及、摘要或证据不足，需补原始方法论文或更多材料。

合并时保留旧断言、冲突、别名和证据；如果语义改变，记录 before/after 和理由。不得为了减少页面数量而把不同机制塞入宽泛“Agent 方法”页。

## 主题路由

围绕读者问题命名，例如“Agent 如何在执行中利用反馈？”而不是“遥感论文 2026”。一页可同时关联领域视图和通用机制视图，但避免为一篇论文创建多个重复入口。当前仓库编译器要求 topic_routes 1–3 项，已有主题优先复用，详情见 pi-intel-wiki.md。
