# 从文献清单到可复用知识

这一轮以知识问题组织内容。一份论文可以支持多个概念页；资料分类用于筛选，不限制页面可以引用的来源。原来的遥感、GIS与自主实验入口保留为资料清单，首页折叠展示，不再作为知识图谱节点或写作候选。

## 已完成的内容

新增六个共享概念：

| 页面 | 复用问题 |
| --- | --- |
| 任务分解与依赖约束 | 交互计划、任务DAG、领域层级和工具分类分别约束什么 |
| 工具知识、选择与流程复用 | API文档、专家流程和成功运行历史怎样帮助执行 |
| 工具接口与中间产物契约 | 参数、产物格式、空间含义与授权条件如何衔接 |
| 工具使用经验怎样进入模型 | 调用筛选、轨迹训练、程序保存和运行时创建的不同更新对象 |
| 计划、执行轨迹与最终结果的分层评价 | 如何区分计划合理、运行成功和目标结果正确 |
| 遥感感知输出怎样成为后续操作的输入 | 文本、对象框、变化掩膜分别可以支持什么后续操作 |

同时更新13个已有页面（包括资料清单），保留旧断言与原文证据，补写双方来源支持的比较。例如：

- Plan-and-Patch保留局部区间两侧文本，HieraPlan保留验证前缀并重规划后缀。共同机制是保留未受影响部分，修补边界不同。
- Toolformer按后续token预测损失筛选API调用，OpenEarthAgent验证多步操作轨迹后监督微调。材料单位、筛选依据和学习目标分别记录。
- RS-Agent提供专家事先设计的流程；PhenoAssistant从成功执行历史整理可复用程序。不能把后者写成已经实现自动检索历史来规划新任务。

Earth-Agent、EarthAgent/HTAM、OpenEarthAgent、OpenEarth-Agent仍是不同研究。工具创建论文将缓存与模板复用列为未来计划，未写成现有功能。GeoGPT早期作者稿与正式版本的差别、GIS Copilot正文与表格的指标分歧继续保留。

## 轻量实现

`wiki_meta`中的`relations`记录实现实例、共同机制、差异对照或组合建议。每条关系包含具体说明、适用范围、断言ID和来源ID；图谱边与节点详情显示说明，而不只显示“相关”。跨研究比较至少有双方来源和原文摘录。普通导航链接仍可保留，但不被当成已经建立了机制关系。

程序校验目标存在、断言与来源关系、摘录存在性以及旧记录保留。表达改写冻结完整关系对象。检查能证明记录与归档材料的对应关系，不能自动证明机制归纳的事实含义；组合建议也不能写成已经实测的收益。

写作候选允许跨资料分类，优先概念页并排除批次清单。已批准原文可以围绕另一个问题再编译，资料处理状态保持不变：

```bash
.venv/bin/python -m station.cli prepare --revisit --source-id <来源ID> --topic "具体知识问题"
.venv/bin/python -m station.cli prepare --source-id <新来源ID> --target <已有页面slug>
```

默认仍为一次LLM调用、一次页面提案，检查后发布。当前没有自动遍历所有文献、补齐所有知识维度或跨页面事务；需要按问题选择材料并复用原文。本轮六个机制页与13个更新由Agent对照归档证据完成，没有额外调用项目LLM。

## 验证

回归覆盖已批准来源复用、跨分类更新、关系出处及目标校验、正文/元数据冻结、图谱说明与清单分离。发布保留配对备份和提案处理记录。现有170项测试通过；本轮还对更新前后的旧断言、冲突及来源关系做了保留检查，并在浏览器验证正文、来源与关系展示。
