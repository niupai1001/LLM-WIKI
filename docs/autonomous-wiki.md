# 自动发布与跨来源 Wiki

2026-10-12。用户取消逐页人工确认，修改通过 Agent 提出。此前的人工发布策略由本轮覆盖。

## 工作流

常规编写保持一次 LLM 调用，额外表达编辑仍按需开启。UI、CLI 和每日编写使用自动发布入口：系统验证引用、原文摘录、页面与来源版本、旧断言保留及 Rewrite 冻结对象，随后保存配对备份、发布并归档。新的或增加支持来源的断言必须附对应原文。明确未解决的事实疑点、缺证据、版本冲突或写入错误保留为系统异常，不要求用户勾选或填写表单。

`/drafts` 改为“编写记录”，展示完成结果和异常。移除四个审核问题、试点评分、批准表单及普通阅读页的人工复核表单；事实记录和历史仍可只读查看。底层 `prepare()`、`--draft-only` 保留开发预览，旧提案 ID 和接口兼容。

## 知识组织

主题入口组织问题与阅读路径；知识条目解释机制、证据和条件。原创方法定义可以单源。跨方法联系要说明共同点、差别与可互补的层次，用双方原文支持，不能仅靠名称链接或来源数量。

编写上下文增加相关既有页面背后的已批准原文，至多四份，与新资料共享字符预算。已发布、引用双方来源的比较段可以在另一方法页展示反向联系；裸链接和共同分类不触发比较。已有知识可用 `revisit=True` 重新综合，来源的采集状态保持原样。

- 更新规划主题入口，按交互决策、显式多步计划、计划修补、时间预算组织阅读。
- 发布已完成版本与冻结检查的上下文表达改写。原正文、元数据和提案处理结果保留在配对备份及归档中。

自动发布不等于自动认定研究结论真实或完成独立复现。系统能验证出处和结构，写作器与 Agent 负责语义核对；未解决问题需要修正或明确记录其范围。
