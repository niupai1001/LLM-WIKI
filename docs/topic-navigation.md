# 概念发布时自动维护主题入口

此前四个主题入口仅直接覆盖9个概念，已有18个概念中的其余9个没有归入入口。卡片还把入口自己的历史来源数显示成“证据数量”，没有表达概念覆盖或当前关联原文。

## 现在的流程

1. 同一遍LLM编写收到原始资料、相关概念和全部现有主题的成员说明。
2. 解释正文与断言的同时，返回`topic_routes`：主题slug、导航问题，以及必要的导航摘要。优先复用主题；确无合适入口时提出新主题标题与摘要。每次可归入1至3个主题。
3. 概念通过原有检查后，程序把它与主题导航一起发布。合并最新成员，保留已有阅读条目和非托管正文；不让模型输出整份入口替换稿。
4. 如果另一个概念已更新同一入口，继续合并成员，保留较新的摘要。普通写入失败恢复概念、入口、元数据和索引；配对备份及处理结果继续保存。

默认仍为一次LLM调用。缺少或无效主题归属的新概念提案不能进入正常发布，避免新增孤立概念；旧草稿保留兼容。表达改写保留已有主题归属。主题摘要描述阅读问题与概念衔接，不产生新的事实断言或独立证据。

## 计数

- 概念数：入口正文直接链接的正式概念页，按slug去重。
- 研究比较数：单独统计`page_role=comparison`的页面。
- 关联原文数：上述页面来源ID的并集，按来源去重。重复引用和多个概念共用同一资料都只计一次。
- 概念卡片显示本页引用来源；入口显示概念、研究比较及关联原文，数量不需要彼此相等。

计数在读取时计算，概念新增来源后随即变化，不依赖入口保存的历史`source_ids`。原始资料分类仍用于筛选；主题导航可以跨分类。

## 验证与边界

隔离回归覆盖同次发布、自动新建主题、并发成员合并、摘要版本保护、失败恢复、旧草稿兼容、表达改写不改变归属和来源去重。真实接口输出也在隔离数据中联调：先纠正本次来源选择，再修复已有关系目标因候选截断而被误拒绝的问题；修复后重放原输出，概念与工具主题一起发布。正式库未发布这份联调正文。

这轮没有增加独立主题模型调用、检索库或跨概念事实更新事务。自动归属与导航摘要仍由模型提出，程序检查格式、目标与发布一致性，不把模型分类当成知识正确性认证。主题合并/拆分、过时概念清理和定期全库重编排仍可由Agent按实际知识变化处理。
